# Model & Hardware Feasibility Study — Chest X-ray VLM on NVIDIA T4

> Goal: determine which open vision-language models can load and run single chest-X-ray inference within a 16 GB NVIDIA T4, and select the main model and a medical baseline for this project.

## 3. Output sanity check

Each model's output was inspected to confirm it produced a coherent radiology-style description rather than garbage:

- **Qwen3-VL-4B**: ✅ coherent PA-view chest X-ray report — correctly identified PA view, normal cardiac silhouette, assessed lung fields/exposure. Structured radiology output, no garbage.
- **Qwen3-VL-8B (4bit)**: ✅ coherent — "posteroanterior (PA) chest radiograph... bony thorax intact, lung fields clear, no consolidation/nodules/masses, cardiovascular silhouette within normal limits."
- **MedGemma-4B (bf16)**: ✅ coherent — objective findings by region (heart size normal, mediastinum unremarkable, lungs clear bilaterally, no effusion/pneumothorax, bones intact). NOTE: only valid in **bfloat16**; see dtype finding below.

### Key finding: Gemma-family must run in bf16, not fp16
MedGemma in **float16** loads and "runs" (8.25 GB, 14.45 tok/s) but emits **only `<pad>` tokens** — fp16 overflows the Gemma activation range (Gemma/MedGemma are trained in bf16). Switching to **bfloat16** produces correct radiology output. The T4 has no native bf16 acceleration but runs bf16 correctly. Qwen3-VL is unaffected and is fine in fp16. The harness now auto-selects bf16 for any model id containing "gemma" (`--dtype auto`).

## 4. GO / NO-GO decision

- **Main subject (conditions A/B)**: ✅ **GO — Qwen/Qwen3-VL-4B-Instruct (fp16)**. Fits at 8.75 GB with ~6 GB headroom for RAG-augmented prompts; fastest at 15.4 tok/s; output is coherent structured radiology text.
- **Larger-model option**: Qwen3-VL-8B (4bit) also fits (7.96 GB) but runs ~3.3× slower (4.66 tok/s) due to 4-bit dequant overhead on Turing. Keep as an optional quality comparison, **not** the default for batch evaluation.
- **Medical baseline (condition C)**: ✅ **GO — google/medgemma-4b-it (bf16, required)**. Fits at 11.48 GB with ~3 GB headroom; 6.37 tok/s (slower, no native bf16 on T4, but correct). Same parameter class as the Qwen-4B subject → a clean, controlled general-vs-medical comparison. Must run in bf16 — fp16 emits only `<pad>`.
- **Rejected / NO-GO**: Llama-3.2-11B-Vision (original plan model) — fp16 does not fit 16 GB (as the plan predicted); superseded by the newer, T4-friendly Qwen3-VL family. Not run.
- **Rationale**: On a 14.58 GB T4, two 4B fp16 models (general + medical) each sit around 8 GB and run at ~15 tok/s — fast enough for batch evaluation over 150–300 images and leaving headroom for RAG evidence injection. The 8B-4bit "squeeze" works but its throughput penalty makes it unsuitable as the primary evaluation model.

### Throughput implications for batch evaluation (≈256 tokens/image)

|---|---|---|
| Qwen3-VL-4B fp16 | ~17 s | ~2.8 h |
